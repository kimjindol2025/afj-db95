## 2. 핫스팟 표본 시도

`perf` 실행 파일은 사용할 수 없어 GDB 대체 경로를 시도했다. 로컬 추출 GDB로 전체 복사본을 실행해 20회 표본을 얻으려 했지만, 세 번 모두 첫 표본에서 같은 오류가 났다.

```text
=== SAMPLE 1 ===
Thread 1 (process <가림> "stage2-compiler"):
Selected thread is running.
```

첫 번째는 GDB `interrupt`, 두 번째는 inferior에 `SIGINT`, 세 번째는 `SIGSTOP`을 보낸 뒤 중단 프레임을 읽으려는 방식이었다. 세 번 모두 GDB가 선택 thread를 실행 중으로 판단했다. 같은 실패가 세 번 발생했으므로 프로파일링을 중단했다. GDB가 남긴 표본은 0개이며, 상위 15 native 함수의 원문 목록과 상위 5 FreeLang 함수의 파일·줄 대응도 확보하지 못했다. 이를 추정해 채우지 않았다.

## 3. 판정 및 제안

현재 확보된 크기·시간 자료만으로는 **(나) 전체 크기에 따라 누적되는 비용**에 가장 부합한다. 4배 입력에서 시간이 2배 미만이고, 2배 입력 구간도 4배 이상 증가하지 않았다. 다만 함수별 스택 표본을 얻지 못했으므로 “비용이 고르게 분포한다”거나 (가)/(다)를 배제했다고 확정할 수는 없다. 함수별 핫스팟 판정은 미완료다.

제안: 컴파일러를 수정하기 전에 GDB를 대화형으로 실행해 inferior 정지와 표본 추출을 검증하거나, 권한이 허용되는 환경에서 `perf`를 준비해 20개 표본을 수집한다. 표본이 확보된 뒤 상위 함수 이름을 `self/*.fl` 정의 위치에 대응시키고 문자열 누적·리스트 append·선형 검색을 살핀다. 이번 회차에는 코드를 변경하지 않았다.
